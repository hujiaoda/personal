# 复现手册（Reproduce Playbook）

> 这个项目的代码是 AI 辅助写成的。本文件的用途：**把 AI 写的代码变成我自己的理解**。
> 每个里程碑验收后，按下面的流程重写一遍对应模块；完成一个再进下一个。

## 总流程（每个里程碑重复一遍）

1. **读**：打开 `PROGRESS.md` 里该里程碑的「复现要点」和「踩过的坑」，
   以及 `docs/architecture.md` 里对应的设计章节。
2. **关**：关掉 `src/` 下该模块的所有参考代码（可以挪走备份，或开一个
   `scratch/` 目录先把自己要重写的文件放进去，跑通后再覆盖）。
3. **写**：不看书、不查参考，凭理解从空文件重写该模块。允许查 Python 标准库
   文档和语言语法，不允许看原实现。
4. **测**：`PYTHONPATH= .venv/bin/python -m pytest` 跑到全绿。
   测试不绿先自己修——修不出来才允许看原实现对照差异，并把差异记进「复现要点」。
5. **比**：把自己的实现和原实现 diff 一遍，找出三处不同设计，写下「我为什么
   会这么写 / 原版为什么那么写」。
6. **记**：把本次重写新踩的坑补进 `PROGRESS.md` 的复现要点（它属于我，不属于 AI）。

## 判断标准

- 能关掉参考，30 分钟内讲清楚该模块的完整数据流和每个设计取舍
- 面试三连问能答：为什么这么设计？哪踩过坑？如果上线要加什么兜底？
- 达标后把模块在 `docs/architecture.md` 的对应行标记「已复现」

## 各里程碑的复现重点

| 里程碑 | 复现核心 | 面试对应考点 |
|---|---|---|
| M0 | 仓库契约测试的写法 | 工程习惯 |
| M1 | `core/loop.py` 的 474 行循环 + `llm/client.py` 的重试/降级 | ReAct、死循环防护、工具失败处理、超时与降级 |
| M2 | 滑动窗口 + 分层摘要 + 长期记忆的接缝 | 记忆压缩、短期/长期记忆 |
| M3 | sql_query 工具 + 自纠错 | Text-to-SQL |
| M4 | FastAPI + 前端的接线 | 应用落地 |
| M5 | 评测集与指标计算 | 指标与迭代（面试官最在意） |

## 时间纪律

- 单次复现 ≤ 2 小时；超时未完成就记下卡点、睡觉，第二天带着问题继续
- 复现永远优先于「让 AI 写下一个里程碑」——理解速度跟不上，代码就只是代码
